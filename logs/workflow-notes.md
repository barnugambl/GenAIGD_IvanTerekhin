### 2. inpaint

**Проблема:** после img2img правая передняя платформа отвлекала: светящийся объект выглядел слишком случайно и не работал как игровой фокус.

**Приём:** локальная маска на нижней правой foreground-зоне. Исправлялась не вся сцена, а только память-шард на платформе, потому что перспектива и общий свет уже работали.

| Зона | Что правили | Результат |
| --- | --- | --- |
| Нижний правый foreground | Шумный/случайный светящийся объект | Получился один читаемый amber memory shard на плите |

**Результат:** файл `04-w07-inpaint-after.png` оставлен, потому что правка стала локальной и естественной. Ещё требует внимания точная форма основания, если кадр пойдёт в final selected.

### 3. outpaint

**Проблема:** после inpaint кадр оставался тесным для будущего скрингена: мало бокового пространства и слишком плотный foreground.

**Приём:** outpaint влево/вправо и лёгкое расширение переднего плана. Цель — не добавить новую локацию, а дать сцене воздух и место для персонажа или UI.

| Направление | Что появилось | Риск |
| --- | --- | --- |
| Left / Right + небольшой foreground | Продолжение галерей, дополнительные архивные плиты, больше пола и боковых витрин | Возможен конфликт перспективы на дальних балконах |

**Результат:** файл `05-w07-outpaint-after.png` оставлен как кандидат на широкий скринген Архива. Шов не бросается в глаза, свет в целом совпадает; дальше лучше проверять depth-контролем, чтобы удержать перспективу галерей.

**Вывод:**
- Для Архива лучше всего сработала связка: `img2img denoise 0.55` для глобального стиля, затем `inpaint` для локального фокуса, затем `outpaint` для расширения композиции.
- `img2img` решает общую проблему палитры и материала, но не должен перепридумывать архитектуру.
- `inpaint` полезен, когда ошибка локальная и не требует менять всю сцену.
- `outpaint` даёт кадру экранное пространство, но требует следующего контроля через `depth`, иначе начинают плыть перспектива и масштаб.
- В следующей итерации сохранить: тёплую сепию, пыльный воздух, amber memory shards, читаемые бетонные галереи и центральную глубину.

- Что хочу контролировать: глубину пространства, перспективу галерей, контур shard, край платформы и читаемость foreground/midground/background.
- Почему выбрал Depth / Canny: `Depth` лучше подходит для многоэтажной архитектуры Архива, а `Canny` — для формы интерактивного объекта, который должен читаться как game prop.

- Model: `sd_xl_base_1.0.safetensors`
- Control mode: `Depth` для сцены Архива, `Canny` для memory shard.
- Input image / sketch / reference: [outputs/selected/hw7/05-w07-outpaint-after.png](../outputs/selected/hw7/05-w07-outpaint-after.png) для Depth, [outputs/selected/hw7/04-w07-inpaint-after.png](../outputs/selected/hw7/04-w07-inpaint-after.png) для Canny.
